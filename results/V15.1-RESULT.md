# V15.1 — does in-place system-message rendering preserve the prefix?

**Date:** 2026-08-12 · **Verdict: CONFIRMED. E7's premise holds.**

## Pre-registered prediction

> E7's premise is proved if stock LCTP ≈ 9.2k while patched LCTP ≈ 100%.
> E7 is dead if patched LCTP is also small.

## Method

Anthropic bodies from `~/e1-dumps/` (13 real captured requests) → faithful port of
`server_chat_convert_anthropic_to_oai()` → `/apply-template` → `/tokenize`.
Longest common **token** prefix between consecutive requests.

Two servers, because llama-server binds its chat template at startup and
`/apply-template` ignores any template in the request body:

| | port | template |
|---|---|---|
| stock | 8003 | GGUF-embedded |
| patched | 8011 | `templates/dsv4-inline.jinja` (`--chat-template-file`) |

Port fidelity was proved first: rendered token count equals the server's own
`/v1/messages/count_tokens` on all 13 captures, delta 0.

## Result

| | total re-read | expensive (>20k) |
|---|---:|---:|
| stock | **423,752 tok** | 3 |
| patched | **14,123 tok** | **0** |

**96.7% of redundant prefill removed.** The three expensive divergences collapse:

| pair | stock | patched |
|---|---:|---:|
| #2→#3 | 133,386 | 2,391 |
| #7→#8 | 139,945 | 1,149 |
| #8→#9 | 140,234 | 396 |

Stock LCP on those three pairs: **9,595 / 9,734 / 9,838 tokens — 6.5–6.7% depth**.
The document estimated "roughly 9,200 tokens in — about 6%". Measured, slightly
deeper, same mechanism.

## Two things the document got wrong or left untested

**1. The post-divergence content is 100% shift-recoverable.** All three expensive
divergences relocate the entire tail verbatim at a shift of only **104–234 tokens**
(`survives 100%`). So the E6 decision rests *entirely* on the SWA claim — that the
server cannot resume mid-sequence — and not at all on the content having changed.
That claim is still untested: **V15.4**.

**2. `analyze-divergence.py` is unsound and its output should not be cited.** It
reports `REWRITE` on 12 of 12 pairs. In 8 of them the only JSON difference is
Claude Code's `cache_control: {"type":"ephemeral"}` breakpoint moving forward —
metadata that never reaches the model. It hashes `json.dumps(message)`, so a
rendering no-op reads as a content rewrite.

## Residual, and why it is not a template bug

Under the patch, #2→#3 still loses 65 tokens (2,391 re-read, 98.3% depth). Detokenised,
the lost tail is an ephemeral *user* message — "The user stepped away and is coming
back. Recap in under 40 words…" — which Claude Code did not retain in the next
request. A genuine client-side content change, unrelated to system-message hoisting,
and cheap because it sits at the very end.

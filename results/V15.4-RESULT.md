# V15.4 — can `--swa-full` recover the discarded prefix?

**Date:** 2026-08-12 · **Verdict: NO. The mitigation does not exist, and #15's stated
mechanism is wrong in detail.**

## The question

V15.2 measured the cost precisely: on all three expensive requests the server prefilled
the **entire** prompt at **0.0% reuse** (142,981 / 149,679 / 150,072) even though a
9,595–9,838-token common prefix was available. That is ~29,000 tokens per session thrown
away on top of what the template problem already costs.

#15 explains it as a sliding-window limitation:

> Reuse is gated on `pos_min >= pos_min_thold`, where the threshold is derived from
> `n_swa`. V4 keeps a 128-token raw sliding window, so the sliding layers retain KV only
> for the most recent 128 positions.

If that were the whole story, `--swa-full` — which makes SWA layers retain everything —
should recover the prefix. The flag *is* plumbed into the DSV4 cache
(`llama-model.cpp:2183`), so the test looked live.

## Result

The server answers at load time, before any request:

```
1.14.467.551 W llama_kv_cache_iswa: using full-size SWA cache (ref: …PR 13194)
1.15.818.907 W srv  load_model: swa_full is not supported by this model, it will be disabled
1.15.975.070 I srv  load_model: initializing, n_slots = 1, n_ctx_slot = 262144
```

**`--swa-full` is accepted, plumbed through, then explicitly disabled for this model.**
No replay was run: the arm is functionally identical to stock and would have reproduced
the stock numbers exactly, at a cost of ~40 minutes.

## Root cause — one hardcoded return, three consequences

`llama-model.cpp:2506-2512`:

```c
int32_t llama_model_n_swa(const llama_model * model) {
    // dsv4 kv-cache has SWA but it cannot be used as a rollback because of
    // other compression ratios, so we return 0 here
    if (model->arch == LLM_ARCH_DEEPSEEK4) {
        return 0;
    }
    return model->hparams.n_swa;
}
```

That single `return 0` produces all three of the following:

1. **`--swa-full` is disabled.** `server-context.cpp:1296-1299` gates the rejection on
   `llama_model_n_swa(model_tgt) == 0`.
2. **The reuse threshold becomes maximally strict.** `server-context.cpp:3299` computes
   `pos_min_thold = pos_next - n_swa - …`; with `n_swa = 0` the threshold is `pos_next`
   itself — *stricter* than the real 128-token window would give.
3. **Context checkpoints are never created.** `server-context.cpp:3468-3475` requires
   `seq_rm_type ∈ {FULL, RS} || n_swa > 0`. With no checkpoint to restore, the search at
   `3351-3383` falls through to `do_reset` → `pos_next = 0; n_past = 0`.

So the reset is not caused by the window being *small*. It is caused by the server being
told there is **no window at all**, which simultaneously removes the workaround flag and
the checkpoint fallback that would otherwise have covered it.

## Corrections to the document

- ❌ "V4 keeps a 128-token raw sliding window, so the sliding layers retain KV only for
  the most recent 128 positions **— there is no stored state at position 9,200 to shift**"
  is not the operative mechanism. The server never learns the window size.
- ✅ The *conclusion* stands: reuse resets to zero, measured at 0.0% on three requests.
- ✅ Dropping E6 was the right call, but for a sharper reason than stated — and the
  document's "the comment reads as unimplemented rather than impossible" instinct about
  `get_can_shift()` applies equally here.

## Upstream opportunity

Reporting the real `n_swa` for `LLM_ARCH_DEEPSEEK4` — or splitting the accessor so the
rollback-safety concern in that comment does not also suppress `swa_full` and checkpoint
creation — would restore ~29,000 tokens of reuse per session on this workload. That is
small next to E7's 436,814, but it is a genuine upstream contribution with a clear
one-line diagnosis, and unlike E6 it does not require implementing compressed-cache shift
semantics.

**Also worth reporting:** the ordering above. `llama_kv_cache_iswa` logs
`using full-size SWA cache` *before* the server disables `swa_full` — the memory appears
to be allocated and then the benefit discarded.

# V15.2 — the template fix in wall-clock, on real hardware

**Date:** 2026-08-12 · **Verdict: CONFIRMED. 96.4% of redundant prefill removed.**

## Method

Two arms of the same server differing in exactly one flag, each restarted to guarantee a
cold cache, each replayed with the same 13 captured request bodies at `max_tokens: 1`:

| arm | flag | context | ubatch | KV |
|---|---|---:|---:|---|
| stock | *(GGUF template)* | 262,144 | 2048 | q8_0 |
| patched | `--chat-template-file dsv4-inline-assistant.jinja` | 262,144 | 2048 | q8_0 |

Reuse read from the Anthropic response itself: `input_tokens` = prefilled,
`cache_read_input_tokens` = supplied by the cache. Their sum is the rendered prompt
length, which cross-checks `render.py` for free.

## Result

| | prefilled | wall |
|---|---:|---:|
| stock | 591,519 tok | **38.8 min** |
| patched | 154,705 tok | **10.5 min** |
| **saved** | **436,814 tok** | **28.3 min** |

73.8% of prefill and 72.9% of wall-clock. Excluding request #1's unavoidable cold
prefill, which both arms pay identically:

| | redundant prefill | time |
|---|---:|---:|
| stock | 452,924 tok | 30.1 min |
| patched | 16,106 tok | 1.8 min |
| **removed** | **96.4%** | |

V15.1 predicted 96.7% from token arithmetic alone. Measured: **96.4%**.

## The three expensive requests

| req | stock | patched | |
|---|---:|---:|---:|
| #3 | 142,981 tok / 551.6 s | 4,374 tok / 25.6 s | **22×** faster |
| #8 | 149,679 tok / 590.4 s | 1,149 tok / 7.8 s | **76×** |
| #9 | 150,072 tok / 592.8 s | 396 tok / 3.7 s | **160×** |

V15.1 predicted #8 = 1,149 and #9 = 396 tokens from `/apply-template` + `/tokenize`
alone. Both matched exactly. The token-level instrument predicts wall-clock behaviour
on this workload.

## What this also confirms about #15

Under stock, all three expensive requests prefilled their **entire** prompt at **0.0%
reuse** — 142,981 / 149,679 / 150,072 — even though a 9,595–9,838-token common prefix
was available. The server does not partially reuse and then fail; it resets to zero,
exactly as #15 claims. That behaviour costs an extra ~29,000 tokens per session beyond
what the common-prefix arithmetic alone predicts, and it is what **V15.4** (`--swa-full`)
will test for a config-only mitigation.

## Caveat before shipping

This is a throughput result. The template moves mid-conversation system reminders from
the prompt head into the conversation body, which is a behaviour change, not a pure
optimisation. **V15.5** (greedy-output agreement, stock vs patched at temperature 0)
still gates deployment.

The `assistant` cutoff was chosen for exactly this reason: it keeps the 35 KB SessionStart
hook hoisted where it was written and moves only the ephemeral reminders. Same cache
benefit, smaller behaviour change.
